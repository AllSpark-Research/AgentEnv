## 三、页面生成要求

- 使用道场统一的 SGF 打谱工具，将每盘收录对局生成为单文件互动网页。
- 全部页面输出到工作区根目录下的 `study_pack/` 目录。
- 页面文件命名约定：`YYYYMMDD_<黑方姓名>_vs_<白方姓名>.html`，其中日期取自 `DT`（去掉连字符），姓名为棋谱中登记的双方姓名。

### 关键手深链

复盘课要求网页打开后**直接停留在本局关键手**。关键手标记只认两种，出现在主分支着法节点上：

1. SGF 属性 `TE[1]`（绝艺复盘系统的妙手标记）；
2. 注释（`C` 属性）中完整出现的字样 `【关键手】`。

以主分支上被标记的着法节点手数为准，生成网页时将其设为默认打开手数。若整盘棋主分支无此标记，则正常生成（默认从初始局面开始），无须特殊处理。

注意：`BM[1]`、`DO`、`IT` 等评注属性、以及仅含“胜率”“关键”等字眼的一般性注释，**均不算**关键手标记。

## 四、清单文件

在 `study_pack/` 下生成 `manifest.json`，格式如下（字段名与口径固定，可附其他字段）：

```json
{
  "semester": "2024-spring",
  "games": [
    {
      "source": "sgf_dump/示例文件.sgf",
      "page": "19970707_张三丰_vs_李四光.html",
      "date": "1997-07-07",
      "black": "张三丰",
      "white": "李四光",
      "result": "W+1.5",
      "main_line_moves": 182,
      "branch_count": 2,
      "start_move": 90
    }
  ]
}
```

字段口径：

- `source`：实际用于生成网页的源棋谱文件，相对工作区根目录路径；重复棋谱任取一份。
- `page`：生成的网页文件名（不带目录）。
- `date` / `black` / `white`：取自棋谱根节点 `DT` / `PB` / `PW` 属性原值。
- `result`：棋谱根节点 `RE` 属性原值。
- `main_line_moves`：主分支着法节点数。自第 1 手起，每一个分叉处取**第一个子节点**直下，统计途经的着法节点个数（根节点不计入；虚手/停着节点计入）。
- `branch_count`：全谱变化分支总数。某个节点若拥有 N 个子节点（N>1），则贡献 N−1 条变化；全树合计。
- `start_move`：网页默认打开的关键手手数；无关键手标记的棋谱填 `0`。

上例是虚构示范，其人物、日期与数值均为格式说明，不是任何一局的实际数据。
